    三个对象，三种职责

    • Draft：稳定稿件 ID、素材、当前文本；每次修改增加 revision。
    • DraftVersion：手动留档与接受候选时的内容快照，恢复不会删除历史。
    • Generation：发起时的稿件 ID、revision、当前内容、参数与目标块；过期结果不能应用。

    下一次生成配置独立保存。手动编辑不改变当前稿的生成来源。

    哪些是真的，哪些是模拟

    • 真实可操作：文字编辑、多稿、本地保存、版本恢复、内容预览、Markdown / JSON 下载、原型意见导出。
    • 本地模拟：延迟返回、候选文本、标签提取、模型离线、生成失败、存储失败。
    • 没有实施：真实模型、产品旧草稿迁移、图片生成 / 图片包下载、自动发布、云同步。

    基础规则与兼容边界

    本原型中，小红书两流程统一采用：短篇 180–240、中篇 320–450、长篇 600 字及以上；标题 25 字以内。公众号篇幅暂用短篇 600–1,000、中篇 1,000–1,600、长篇 1,600–2,400 的提议值，需单独确认。

    字数按 Unicode 字符计数（不含空白），不等同于 token 数。检查以当前正文生成时的篇幅为准，改变下一次参数不会重新定义旧稿的标准。

    建议审核路径 · 约 7 个场景

    1. 先编辑正文，保存后刷新；切换稿件再回来。
    2. 改语气 / 模型，并模拟离线，观察原稿。
    3. 生成候选期间继续编辑，验证过期保护。
    4. 修改主题词后生成标签，查看实际上下文。
    5. 恢复一个版本、导出文本，再记录意见。

    手机布局：导航横排，编辑区在前，设置与检查在后。建议实机检查 390 / 768 / 1024 / 1440 宽度与中文输入法。

    设计延续 前序优化预览 的暖色、纸面与橙色强调，收敛到可编辑、可恢复的内容工作台。打开完整改善审核清单 ↗
