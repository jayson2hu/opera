## 1. 已合并的产品方向

保留「公众号创作 → 转为小红书新稿」「长文改写小红书」「小红书原创」三条流程及用户默认入口。共同目标是让用户保有文本控制权：可离线手写、继续编辑、独立留稿、版本回看、确认 AI 候选、复制与导出。延用现有 SplitFlow、手机预览、主题、图片上传/导出，不把离线原型的模拟功能接进正式产品。

本轮没有新增云端账号、同步、自动发布、实际平台审核、传播效果预测、付费能力或模型模拟开关。

## 2. 稿件存储与迁移

| 项目 | 当前约定 |
|---|---|
| 单稿键 | opera-draft-{composer / adapter / wechat}-{uuid} |
| 当前稿索引 | opera-active-draft-{flow} |
| 记录外层 | schemaVersion=2、递增 revision、value、savedAt、versions、可选 migratedFrom |
| value | 用户输入、当前正文、下一次配置、来源篇幅用的 resultParameterKey；保留结构合法但未完成的手写结果 |
| versions | 深拷贝完整 value；内容相同去重，不静默裁剪历史 |
| 旧稿 | 同步读取 *-current 及原来保存的记录，首次保存迁移到独立 ID，旧字节保留 |
| 迁移索引 | opera-migrated-{旧键}；防止删除新版后旧备份重新出现 |
| 新稿 | 新建独立 ID，不覆盖当前稿或另外一条流程 |
| 自动保存 | 1500ms 防抖；应用内切换 / pagehide / beforeunload / 页面隐藏时尝试同步 flush |
| 保存失败 | 显式提示，正文保留内存；默认阻止切换，用户明确确认已备份后才能继续离开 |
| 损坏数据 | 解析失败或正文结构不兼容时禁止自动覆盖，原存储保留；结构不兼容的 payload 放进导出备份的 unreadableOriginal |
| 版本恢复 | 先留存恢复前稿件，再恢复选中内容/主题/语气/篇幅；保留历史并追加恢复快照，模型沿用当前选择 |
| JSON 备份 | 导出当前内容和版本；没有通用文件导入界面，不代表云同步 |
| 显式删除 | 需用户确认；删除失败不提示成功；清空仅作用于草稿、旧公众号稿箱与索引，不清偏好/创作统计 |

限制：localStorage 的 revision 检查不是跨窗口原子事务，推荐同稿单窗口编辑，不提供协作保障。崩溃/强杀不保证触发关闭事件；不能承诺防抖窗口内零丢失。清理浏览器数据会失去本地稿件。当前未保存的内存内容与已保存记录是两回事。

图片仍是临时 File / Blob URL，不写入 JSON。刷新后须重新选择，当前版本恢复也不恢复临时图片。公众号封面/内嵌图中的装饰示例不是已生成、可发布的图片素材。

## 3. 编辑与候选契约

1. 正文支持全文编辑与段落改写。手写不依赖模型；标题/摘要不再静默截断，超建议篇幅显示提醒。
2. 段落改写只调用真实改写接口，返回候选。可手工调整候选后应用；放弃不会改原文。
3. 首次生成、整稿重生成和标题/摘要/标签/正文单块生成均先形成候选；SSE 中间值不写入当前正文。
4. 候选记录请求时的稿件 ID 和完整正文结构指纹。原稿、相邻段落或其他结果字段发生变化时，旧候选禁止覆盖，要求重新生成。
5. 显式应用前留存原稿版本。没有保存成功时不应用整稿候选；保存失败时用户可先导出备份。
6. 单块生成只校验本次输出块，允许其他人工字段未完成；整稿生成仍要求所有必要结果齐全。空正文、空标签结果、错误、拒答或中断不成为完成稿。
7. 可以取消生成，请求卸载时中止；迟到的已取消任务不能回写。已存在的稿件不需要通过旧参数一致性校验才可显示。
8. 未确认候选只在当前页内存中；离开稿件或刷新将丢弃候选，界面已明确提示。

配置改变不会清空稿件。来源篇幅与下一次生成配置分别处理：只重生成标题/标签/摘要不改变正文的来源篇幅；重生成正文或整稿后，在用户应用时更新来源篇幅。来源配置是请求记录，不是服务器签名或完整模型审计凭证。

## 4. 前后端局部生成接口

接口保持原路径与 SSE 事件：

| 路径 | regenerate | 当前内容路径事件 |
|---|---|---|
| POST /api/compose | title / body / tags | step(目标) → 目标事件 → step(done) |
| POST /api/wechat/compose | title / digest / body | step(目标) → 目标事件 → step(done) |
| POST /api/rewrite-paragraph | 原有 text + instruction | 原有 JSON 响应；前端先作为段落候选 |

两个 compose 请求新增可选 currentContent，例子：

    {
      "topic": "关于如何长期坚持内容写作的经验",
      "contentType": "story",
      "tone": "knowledge",
      "targetLength": "short",
      "regenerate": "tags",
      "currentContent": {
        "title": "用户当前标题",
        "body": "用户已经编辑过的当前正文及事实。",
        "draftId": "opera-draft-composer-example",
        "revision": "本地内容指纹的短跟踪值"
      }
    }

公众号请求用 articleType 替代 contentType，currentContent 可以包含 digest。

| currentContent 字段 | 约束 |
|---|---|
| title | 必填字符串，最多 500 字符，允许空标题 |
| body | 必填非空白字符串，最多 20000 字符 |
| digest | 可选字符串，最多 2000 字符，默认空字符串 |
| draftId / revision | 可选字符串或 null，每个最多 128 字符；只用于请求跟踪，不是权限或并发凭证 |
| 其他键 | 拒绝，HTTP 400；错误内容不回显用户正文 |

传入合法 currentContent 且指定 regenerate 时：

- 直接使用当前稿件上下文，只生成目标块；不先做隐藏提炼、标题和全文生成。
- tags 只调用一次模型，使用当前标题/正文及正文末尾内容，不再偷偷截到前 4000 字。
- body 只执行一次有 token 预算的流式生成；title / digest 为一次 JSON 生成。
- 仍沿用模型 allowlist、连接/预算限制、安全错误和断开检测。
- 返回 done 只表示协议上的生成完成，不表示用户已应用或平台审核通过。

旧客户端不传 currentContent（或传 null）时保留旧路径和旧 SSE 协议，包括旧标签路径的隐藏生成成本。前端新版本会在局部生成时传当前内容；不建议新客户端继续使用旧标签路径。

## 5. 篇幅和检查

| 流程 | 精简 | 标准 | 详细 |
|---|---|---|---|
| 小红书原创 | 180–240 | 320–450 | 600+ |
| 长文改写小红书正文 | 300–500 | 600–900 | 1000+ |
| 公众号 | 500–800 | 900–1400 | 1600+ |

上述目标来自现有后端提示词，是写作建议，不是平台强制限制。前端按非空白 Unicode 字符计数，包含标点。生成模型不保证严格命中范围，因此界面按实际正文给解释性提醒，不把偏离范围的用户文本删掉。

原创标题建议 15–25 字、标签目标 6–10 个；公众号标题建议 14–32 字、摘要 60–120 字。改写流程仅对首个候选标题进行长度检查，其他标题/卡片需人工核对。图片权利、数字、引语、经历真实性及图文一致性必须由人审核。无完读率、互动潜力等预测百分比，无“基础项达到即适合发布”的结论。
