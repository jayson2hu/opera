## 合并后的目标与范围

以真实可编辑、可恢复、可交付的内容工作台为目标，保留公众号创作、长文改写为小红书、小红书原创三条流程。沿用现有 React / FastAPI、设计 token、SSE、真实段落改写、卡片图片导出和个人偏好。不把离线原型中的模拟模型、异常开关或审核面板带入正式产品。

依据：[原设计计划](FRONTEND-OPTIMIZATION-DEV-PLAN.md)、[改善审核清单](product-improvement-review-2026-09-10.html)、[可操作原型](preview/product-improvement-prototype-2026-09-10.html)。本轮用户已授权按设计与计划开发并合并取舍；原型中的独立审核选择不作为额外已签字证据。

## 验收边界与下一步

本轮测试不是实机验收：SSR 验证实际 Page 初始化和已渲染控件；保存 hook 测试验证真实同步回调，但不运行浏览器 effect、1500ms 定时器、beforeunload、焦点和布局。完整手工矩阵见 [契约与验收手册](DRAFT-WORKSPACE-CONTRACT.md)。

1. 在可用的应用内浏览器或人工环境执行三流程普通进入、刷新、同流程切稿、版本恢复、候选应用/放弃/过期、取消生成和弱网中断。
2. 验证 390 / 860 / 1440 / 1920 宽度、浅深色、全键盘、对话框关闭/焦点返回、中文输入法、复制及图片导出；失败/空间不足用独立测试浏览器资料验证，勿填满真实用户存储。
3. Docker smoke 保留此前暂缓决定，本轮不擅自重跑。真实模型全流程在明确允许消耗配额后再验收。
4. 后续若把图片资产持久化或多窗口协作纳入范围，应单独设计 IndexedDB/服务端存储与迁移，不把当前本地 JSON 稿件误当完整云稿箱。
